# D3.9 — runtime animation bridge: validation correction

## Result

The initial bridge implementation was committed, but the OoT link step rejected it. The symbols `LinkAnimation_PlayOnce` and `LinkAnimation_PlayLoop` are declared in the shared header but are not linkable symbols in this OoT patch build.

The bridge call has therefore been removed from the active OoT runtime until it can be routed through a verified engine entry point. This avoids leaving the prototype with unresolved linker references.

- D3.7 imported Deku animation definitions remain in `data/defs/link-animations.yml`.
- The animation importer still resolves source frame offsets from MM animation headers and emits generated animation declarations.
- D3.8 action mapping remains valid as a reference map.
- No ROM or save data was modified.

## Validation

- The D3.9 workflow reached the OoT link stage and failed on the two unresolved animation symbols.
- This is a real compile/link failure, not a ROM build or runtime test.
- A verified OoT engine call path is required before wiring `pn_gurd` or other imported animations into gameplay.
