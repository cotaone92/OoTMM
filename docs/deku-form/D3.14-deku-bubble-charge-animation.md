# D3.14 — Deku bubble charge animation and spawn guard

## Implemented

- While B is held in Deku form, the runtime starts the imported `gPlayerAnim_pn_tamahaki` track once, guarded by the generated `COMBO_IMPORTED_ANIM_GPLAYERANIM_PN_TAMAHAKI_FRAMECOUNT` macro.
- The call uses the OoT overlay entry point already verified by the existing Deku guard integration; it does not introduce a new unresolved animation symbol.
- Charge animation state is reset when charging is interrupted, the player leaves Deku form, or the player/scene context changes.
- The projectile spawn result is checked. The charge is cleared after the release attempt, and B remains intercepted only in Deku form; human B-button behavior is unchanged.

## Limits

- The imported animation track is a provisional charge pose; timing and visual fit require an in-game ROM test.
- The `pn_tamahakidf` alternate track is not selected yet.
- Magic consumption remains intentionally unimplemented until the exact OoT magic state and callable routine are verified.
- No final MM bubble mesh, growth/hover, bounce, impact effects, or audio are claimed.
- No ROM build or in-game test has been performed.

GitHub Actions must pass the branch's C/TypeScript validation and automated tests for this commit. CI success validates source compilation/tests only; it is not proof of a generated ROM or gameplay behavior.
