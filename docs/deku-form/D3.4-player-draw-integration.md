# D3.4 — Deku player draw integration

## Scope

D3.4 connects the imported Majora's Mask Deku LOD skeleton to the OoT player draw path. This is source integration only. It is not yet a build, ROM, or emulator acceptance result.

## Implemented

- Added a transient OoT Deku form state API in `packages/generator/src/oot/actors/Player.c`:
  - `OotDekuForm_Set(play, player, form)`
  - `OotDekuForm_IsActive(play, player)`
  - `OotDekuForm_Reset()`
- State is runtime-only. It does not modify `Player`, `SaveContext`, or save data.
- State binds to the current `PlayState*`, `Player*`, and scene ID; changing the play state, player instance, or scene resets to Human.
- `hookPlay_Init()` resets the state before the play state is initialized.
- Added `Player_GetDekuObject()`, which resolves `CUSTOM_OBJECT_ID_DEKU_LINK` through `Object_GetSlot` and `Object_IsLoaded`. It handles normal object slots and extended slots through `gExObjectsAddr`. It does not cache a slot or object pointer.
- Extended the existing `Player_DrawFlexLod` wrapper:
  - When Deku is active and the custom object is loaded, it binds the object's memory to segment 6 for OPA and XLU.
  - It resolves `CUSTOM_OBJECT_DEKU_LINK_0` as a `FlexSkeletonHeader`.
  - It passes the header's segmented limb-pointer array to `SkelAnime_DrawFlexLod`, not the header itself.
  - It uses the header's own `dListCount`; it does not assume that the two LOD alternatives equal the matrix count.
  - It validates the 21-limb model against the OoT player joint-table capacity and uses a neutral joint table while preserving the player's root translation and rotation.
  - It passes no human limb override or post-draw callbacks, preventing OoT hands, weapons, shields, boots, and gauntlets from being attached to the Deku skeleton.
  - It restores CPU segment 6 and emits the restored segment to both OPA and XLU before returning.
- Exposed the runtime state API in `packages/generator/include/combo/oot/player.h`.

## Header contract

The imported object uses the normal `FlexSkeletonHeader` layout: the embedded `SkeletonHeader` contains the segmented limb-array pointer and limb count; `dListCount` is the trailing header field. The D3.3 LOD importer reads the limb count from the embedded skeleton header and relocates each 16-byte LOD limb's near/far display-list pointers.

## Not included yet

- No transformation input or animation switching is wired in D3.4. D3.5 will call the state API to activate/deactivate Deku.
- No Deku movement, hovering, water behavior, collision dimensions, item restrictions, or dedicated animations.
- No pause-menu preview or HUD changes.
- The current draw path uses a neutral pose; it is intended to establish model rendering before animation integration.
