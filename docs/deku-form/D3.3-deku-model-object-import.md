# D3.3 — Deku model object import

## Status

Source integration is committed on the development branch. Static source checks were added to fail fast on malformed source data and missing display-list references. TypeScript typecheck, generator execution, ROM build, and in-game rendering remain unrun.

## Source facts verified

- Source object: Majora's Mask `objects/object_link_nuts`.
- XML metadata declares `gLinkDekuSkel` at segment address `0x0600ba24`.
- The skeleton is declared `Type="Flex"` and `LimbType="LOD"`.
- XML lists 21 LOD limbs, beginning at object offset `0xB880` and ending at `0xB9C0`, in 0x10-byte steps.
- The object importer registers the relocated skeleton header as `CUSTOM_OBJECT_DEKU_LINK_0`; the object ID is generated as `CUSTOM_OBJECT_ID_DEKU_LINK`. Neither numeric value is hardcoded.

## Changes

- `ObjectEditor` now relocates the two display-list pointers (+0x08 and +0x0c) in each 16-byte LOD limb.
- The LOD limb pointer table is copied and each of its 21 entries is relocated.
- The Flex skeleton header is copied and its limb-table pointer is replaced with the relocated table. Other header fields are preserved.
- Import validation now rejects:
  - a truncated source object or missing 12-byte skeleton header;
  - a skeleton limb count other than the 21 entries declared by the XML;
  - a missing or truncated limb table;
  - null limb pointers;
  - a missing or truncated 16-byte LOD limb;
  - nonzero near/far display-list pointers that do not resolve to source display lists.
- `CustomObjectsBuilder` adds `DEKU_LINK` to the generated custom object list and checks that the skeleton header is the first exported offset.

## Runtime contract

The runtime loader must resolve `CUSTOM_OBJECT_ID_DEKU_LINK` through OoT's extended object-slot mechanism and set segment 6 to that loaded object before drawing. It must consume `CUSTOM_OBJECT_DEKU_LINK_0` as the skeleton-header offset. It must not retain a raw object pointer or slot across object-context resets.
