# D3.3 — Deku model object import

## Stage closure

**Source-integration scope: closed. Build/runtime acceptance: pending.**

The development branch now contains the LOD importer, Deku custom-object registration, defensive source-data checks, and the documented runtime contract. This closes the code-authoring portion of D3.3. It does not certify a successful generator run, ROM build, or in-game render.

## Verified source facts

- Source object: Majora's Mask `objects/object_link_nuts`.
- XML declares `gLinkDekuSkel` at object offset `0xBA24`, segment address `0x0600ba24`.
- XML declares the skeleton `Type="Flex"` and `LimbType="LOD"`.
- XML declares 21 LOD limbs, at offsets `0xB880` through `0xB9C0`, in 0x10-byte steps.
- The custom object builder registers the object as `DEKU_LINK`; generated symbols are `CUSTOM_OBJECT_ID_DEKU_LINK` and `CUSTOM_OBJECT_DEKU_LINK_0`. Numeric IDs/packed addresses are generated, not hardcoded.

## Implemented source changes

- `ObjectEditor` processes 16-byte LOD limbs and relocates both near/far display-list pointers.
- Its display-list walker handles nested `G_DL` references and relocates referenced vertex, texture, and palette data through the existing object-editor pipeline.
- The 21-entry LOD limb pointer table is copied and each limb is relocated.
- The Flex skeleton header is copied and its limb-table pointer is replaced; remaining header bytes are preserved.
- Import validation rejects a truncated object/header/table/limb, a limb count other than 21, null limb pointers, and unresolved nonzero near/far display-list pointers.
- `DEKU_LINK` is included in `CustomObjectsBuilder.build()`; the relocated skeleton header is submitted as the object's first exported offset.

## Runtime contract for D3.4

Resolve `CUSTOM_OBJECT_ID_DEKU_LINK` through OoT's object-slot system. Set segment 6 to the loaded object before drawing and use `CUSTOM_OBJECT_DEKU_LINK_0` as the skeleton-header offset. Do not cache object pointers or slots across object-context resets. Do not connect the player draw callback until the generator output has been inspected and the model can be shown to render.
