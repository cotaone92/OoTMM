# D3.17 — Charged bubble scale and collision

## Implementation
- Corrected the native OoT bubble draw scale: the original `gBubbleDL` is drawn at unit actor scale, with expansion applied in the draw matrix. The previous tiny actor scale was not consistent with the native OoT `EnBubble_Draw` implementation.
- The B-charge value (clamped to 0–30) now controls a modest expansion from 1.0× to 1.3×.
- The cylinder collider is resized from a 16-unit radius / 32-unit height baseline using the same expansion factor and is vertically centered around the visible bubble.
- Kept the existing projectile speed curve, lifetime, wall/floor/ceiling termination and native object dependency.

## Reference
The scale and billboard approach follows the native OoT `EnBubble_Draw` pattern: billboard rotation, expansion matrix and `gBubbleDL`. The OoT source uses a joint-sphere collider; this implementation retains the current cylinder collider, scaled to track the visual bubble. It is an approximation, not a byte-for-byte port of the original collision system.

## Validation boundary
CI will validate source compilation/typecheck and automated tests. The bubble's actual visual bounds and collision contact still require a generated ROM and in-game testing; those have not been performed.
