# D3.13 — Deku bubble input and charge

## Implemented

- The Deku form intercepts the B-button path inside `Player_ProcessItemButtonsWrapper`.
- Holding B accumulates a charge from 0 to 30 frames.
- Releasing B spawns `ACTOR_CUSTOM_DEKU_BUBBLE` in front of the player, using the player's facing yaw.
- The charge is passed in the actor params. The projectile clamps it to 30 and scales its initial speed and visual scale from that value.
- B press is consumed only while Deku is active. Human-form sword and item behavior, including existing mask B actions, remains on the original path.
- Charge state is cleared when the player leaves Deku form, changes scene/player context, or becomes unable to fire.

## Deliberate limitations

This is the first input-to-projectile connection, not the final MM-equivalent bubble weapon:
- No magic cost is charged yet. The correct OoT magic routine and its ABI must be verified before calling it; no guessed symbol or address is used.
- The imported `pn_tamahaki` / `pn_tamahakidf` tracks are not yet bound to the charging and firing states.
- Projectile mesh, bubble growth/hover, bounce behavior, impact particles and sound are still provisional.
- The projectile's collision and firing behavior still require in-game testing.

## Validation

The changes are committed to `dev/majora-of-time-deku-prototype`. GitHub Actions must pass TypeScript/C compilation and tests before this step is considered source-validated. A successful CI run is not a ROM build or an in-game test.
