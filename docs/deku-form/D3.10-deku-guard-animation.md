# D3.10 — Deku guard animation bridge

## Implemented

- The OoT shielding state is read from `PLAYER_STATE1_SHIELDING`; no new input binding is introduced.
- When Deku is active and shielding changes from inactive to active, the runtime starts the imported `gPlayerAnim_pn_gurd` animation as a loop.
- The animation is started only on the rising edge, not every frame, preventing the animation from being reset continuously.
- The edge state is cleared when the player/scene context is rebound and whenever shielding or Deku form is no longer active.
- The runtime calls the OoT overlay entry point `LinkAnimation_PlayLoopSetSpeed` at `0x8008C298` through a typed function pointer. This exact entry point and address are already used by `packages/generator/src/oot/actors/Item/Item_Kamaro.c`; this avoids the unresolved external symbol failure from the first D3.9 attempt.
- The imported animation symbol is generated from ROM inputs. Its availability is detected with `COMBO_IMPORTED_ANIM_GPLAYERANIM_PN_GURD_FRAMECOUNT`; the runtime declaration and guard-animation code are compiled only when that generated macro exists. This keeps source-only CI builds (which use the checked-in header without ROM-specific imports) valid, while enabling the feature in a ROM build that has generated the Deku animation.

## Scope and limitations

This connects the Deku guard pose to OoT's existing shielding state. It does not yet implement Deku-specific shield collision, damage reduction, projectile reflection, guard stamina, or a custom guard input/action. Those require separate gameplay work and in-game validation.
