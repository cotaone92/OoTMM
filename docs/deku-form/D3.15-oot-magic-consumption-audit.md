# D3.15 — OoT magic-consumption integration

## Status

**Runtime integration added; automated validation pending.** The Deku bubble now requests OoT magic only after its projectile actor has been allocated. If the request is rejected, the new actor is killed and no projectile is fired.

## Verified OoTMM integration path

- `packages/generator/include/combo/magic.h` declares `Magic_RequestChangeCustom(PlayState*, s16, s16)` and the OoT request type `MAGIC_CONSUME_NOW`.
- `packages/generator/src/oot/z_parameter.c` implements `Magic_RequestChangeCustom`. It applies the existing Chateau Romani rule and forwards the request to the original OoT `Magic_RequestChange` routine.
- The same wrapper is already connected to the existing player magic-arrow call site with `PATCH_CALL(0x80832578, Magic_RequestChangeCustom)`.
- The upstream OoT implementation in `src/code/z_parameter.c` verifies that `MAGIC_CONSUME_NOW` rejects requests when magic has not been acquired, when the available amount is insufficient, or while the meter is in a conflicting state. On acceptance it sets the target and enters the normal consume state machine. No direct writes to magic fields are needed.

## Original Deku bubble cost

The Majora's Mask player implementation defines:

- `sMagicArrowCosts[]`: Fire 4, Ice 4, Light 8, Deku Bubble 2.
- `func_808305BC` requires at least 2 magic units for the Deku form bubble, except for the documented Clock Town bowling exception.
- `func_808306F8` spawns the bubble actor first and then calls `Magic_Consume(play, 2, MAGIC_CONSUME_NOW)` when the actor exists.

Source: `zeldaret/mm/src/overlays/actors/ovl_player_actor/z_player.c`, commit `b19a78c47dfbb19a3b23447a208b7248527d4276`.

The OoT prototype uses the same fixed cost of **2 magic units per bubble**, independent of charge strength. The Clock Town bowling exception is not relevant to the OoT prototype.

## Runtime changes

In `packages/generator/src/oot/actors/Player.c`:

1. Include `combo/magic.h` and define `DEKU_BUBBLE_MAGIC_COST 2`.
2. On B release, attempt to allocate `ACTOR_CUSTOM_DEKU_BUBBLE` first.
3. Only if the actor exists, request `Magic_RequestChangeCustom(play, DEKU_BUBBLE_MAGIC_COST, MAGIC_CONSUME_NOW)`.
4. If the request fails, immediately kill the allocated actor. This prevents a free shot when magic is missing, insufficient, or the meter is busy.
5. If actor allocation fails, no magic request is made, so no magic is spent.

This preserves the original OoT magic meter state machine and the fork's existing Chateau Romani behavior. It does not guess a runtime address or manually edit save/magic state.

## Validation gate

- The fork's `Fork Validation (No Deployments)` workflow must pass C compilation/typecheck and tests for the final commit.
- CI success validates the source integration and linkability within the configured build; it does not constitute a ROM build or an in-game test.
- Actual HUD timing, sound feedback, and gameplay behavior still require a generated ROM and in-game validation.
