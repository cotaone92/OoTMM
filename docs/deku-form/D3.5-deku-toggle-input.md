# D3.5 — Controlled Deku form toggle

## Goal

Provide a reversible, low-conflict input to activate the D3.4 visual Deku draw path and return to the OoT human model.

## Input

- **L shoulder button (N64 L_TRIG):** toggles Human <-> Deku.
- The handler runs in `Player_UpdateWrapper` after the original OoT player update and reads the existing controller input pointer.
- The press is consumed when the toggle is accepted, so it cannot leak into another handler.
- The toggle is ignored while Link is holding an item, is cutscene-frozen, is using an item, or is riding an actor.
- D-pad inputs remain untouched because OoTMM already assigns them to its D-pad item functions.
- No new menu, save flag, inventory item, or ROM configuration is added.

## Runtime behavior

- The toggle calls `OotDekuForm_Set()` using the transient state introduced in D3.4.
- Toggling back selects Human and lets the existing human player draw path run again.
- Scene/player/PlayState changes still reset the state to Human.
- If the custom Deku object is not yet loaded or the skeleton header fails validation, D3.4 falls back to the human draw path rather than suppressing the player entirely.

## Scope boundary

D3.5 is an input/control integration for a **visual model prototype**. It does not yet convert Link's movement, collision, animations, item use, water behavior, or abilities into Deku behavior. Those belong to later form-gameplay stages.

## Test procedure after a build is available

1. Start an OoT game and wait until Link is controllable.
2. Tap L once; the intended result is the imported Deku model.
3. Tap L again; the intended result is the original human model.
4. Repeat while targeting, moving, and after changing scenes.
5. Verify that the D-pad item functions, B actions, C-item actions, and pause menu remain unaffected.
6. Verify that cutscenes, item-use animations, and riding do not trigger the toggle.
