# D3.8 — Deku animation action map and runtime gate

## Status

Source-level action mapping is complete. Runtime animation dispatch is **not enabled** in this step. This is deliberate: the imported D3.7 set is a collection of special-purpose Deku animations, not a complete locomotion set, and the OoT player action machine has not been ported from Majora's Mask.

## Verified runtime facts

- OoT's player owns a `SkelAnime skelAnime` and separate joint/morph tables (`packages/generator/include/combo/oot/player.h`).
- The imported-animation frame loader in `packages/generator/src/common/animations.c` intercepts player-frame DMA requests. It translates segment-8 imported headers to the source game's `link_animetion` VROM range. It does **not** choose an animation for the player.
- `Player_DrawFlexLod()` currently renders the Deku skeleton using the player's current joint table. It does not replace the animation state.
- Therefore, setting the imported header pointer alone is insufficient. A valid runtime transition must use the game's Link-animation change path, keep the correct loop/once mode and frame bounds, and be invoked by the corresponding player action rather than every frame after the original OoT update.

## D3.7 imported animation semantic map

The following uses were checked against the Majora's Mask player source. They are not interchangeable with generic idle/walk/run animations.

| Imported animation | Verified use in Majora's Mask | Runtime eligibility |
|---|---|---|
| `pn_Tbox_open` | Deku chest-opening animation slot | Only chest-open action |
| `pn_attack` | Deku flower-ground attack sequence | Only matching flower/ground attack state |
| `pn_batabata` | Loop while struggling in a bubble | Bubble-captured state only |
| `pn_doorA_open`, `pn_doorB_open` | Left/right door-opening animation | Matching door action/direction |
| `pn_drinkstart`, `pn_drink`, `pn_drinkend` | Bottle drinking start, loop, and end | Matching drink action phases |
| `pn_gakkistart`, `pn_gakkiplay` | Ocarina start and play | Ocarina action |
| `pn_getA`, `pn_getB` | Item-get variants | Matching item-get action |
| `pn_gurd` | Deku shield/guard animation | Guard action |
| `pn_kakku`, `pn_kakkufinish` | Deku flight/glide sequence and its finish path | Matching glide state only |
| `pn_maskoffstart` | Form-change/mask-off start sequence | Transformation sequence only |
| `pn_rakkafinish` | Deku flight/landing finish path | Matching landing/flight-exit state |
| `pn_tamahaki`, `pn_tamahakidf` | Deku bubble projectile upper-body animation variants | Matching Deku projectile action; upper-body track must be handled separately |

## Missing before a safe general animation dispatcher

1. Identify and import the Deku idle, walk, run, turn, jump, fall, landing, and fidget animations used by the MM player. They are not among the 19 D3.7 entries.
2. Port or explicitly map the corresponding OoT action transitions. OoT action functions and state variables are not interchangeable with MM's.
3. Resolve the target game's Link-animation change entry points and call contract from the exact OoT build. Do not hand-edit `SkelAnime` fields as a substitute.
4. Define how the upper-body animation track and the Deku skeleton's limb layout are handled for bubble shots, shields, and carried items.
5. Add build-time checks that every animation symbol used by the runtime table is emitted for the OoT target.
